## Что это и для кого

Дашборд на Streamlit «Модель экономики» — **учебный инструмент**: заказчик строит собственную ментальную модель
экономики и рынков. Отсюда правила подачи (их держать на каждом экране):
- на экране — **ответы по данным, а не вопросы** («ФРС тормозит экономику», а не «тормозит ли ФРС?»);
- каркас `core/learn.py`: шапка слоя → главный вывод (`takeaway`) → числа → графики → «💡 Как это работает» →
  «📊 Показать на реальных данных» (примеры: **как механизм работает обычно** и **когда ломается**);
- у каждого сигнала метки: тип по времени и надёжность (`learn.tags`); сигнал без проверки на истории не показываем;
- цифры в текстах — из данных (f-строки), не по памяти; оценки помечаем как оценки, допущения — как допущения;
- справка `views/v2/help.py` пополняется с каждым шагом: глоссарий + «Что нового» (`CHANGELOG`, новое — сверху).

Общение с заказчиком — по-русски, коротко, без жаргона. У заказчика ограничена квота: читать файлы точечно, не
делать лишних проверок, полный тест гонять один раз перед коммитом.

## Как работать

- **Тесты**: `uv run python tests/test_app.py` — прогон всех экранов через AppTest, ~5–7 минут, запускать в фоне.
  Новый экран слоя — добавить `check_layer(page, [ключи примеров], имя)`; переключатель периода у слоя — с ключом
  `period` (его ждёт `check_layer`).
- **Деплой**: коммит сразу в `main` (без веток, так договорено) → `git push origin main` →
  `sudo -n systemctl restart economy-model`.
- Данные: `core/series.py` (каталог) + `core/data.py` (источники: fred, yf, shiller, fed, nyfed, cbr, cftc, finra;
  кэш в `data_cache/`). FRED нельзя запрашивать с User-Agent `Mozilla/5.0` — блокирует. Облигации РФ — Мосбиржа ISS
  (`core/moex.py`).

Что показала проверка на истории (это уже в примерах на экране, не переоткрывать):
- работает: эффект смены месяца (ослаб после 2010), продажа доллара в конце месяца после роста S&P (t ≈ −2,4),
  тренд как защита в затяжных распродажах, маржинальный долг как предупреждение;
- физлица на Мосбирже торгуют против движения (связь за неделю с РТС ≈ −0,46, одинаково в 2021–23 и 2024–26);
- не видно в простых тестах: крайние позиции физлиц Мосбиржи не предсказывают курс/индекс; ребалансировка конца квартала (Harvey et al. видят по точным потокам), продажи фондов
  с таргетом волатильности не предсказывают дальнейшего падения, крайние позиции CFTC не предсказывают месяц вперёд.

## Соседний проект trade-news

`/opt/trade-news` — отдельный сервис со своей сессией Claude (сборщик новостей и событий). Делим так: trade-news
**собирает датированные события и копит данные**, дашборд **считает модели и учит**. API на этом же сервере без
авторизации (`http://127.0.0.1:10000`, переменная `TRADE_NEWS_URL`):
- `GET /api/calendar?from&to&types&markets&major` — календарь вынужденных потоков (типы и поля — README trade-news);

## Что дальше (на 25.10.2026)

**Сделано: «Торговля» → «Целевая функция»** (`views/chain/objective.py`, `core/trading.py`): 4 вопроса → профиль
(гладкость / сырое матожидание / доход на час внимания / сложный процент) → стиль, частота, риск, цель в R;
моделирование кривых (0,5/1/2%, ½ Келли, Келли) с трением в R; блок «преимущество завысили на 10 п.п.».
Значения по умолчанию — намеренно скромное преимущество (+0,06…0,13 R), чтобы не показывать сказочных кривых.

**Следующая — страница «Откуда edge / есть ли сделка сегодня»** (одобрено 25.10): основа — конспект главы 7 книги,
`reports/Книга — глава 7 Откуда edge.md`. Рамка BAIT на крипте (информационный — забыть кроме мелких токенов;
аналитический — специализация; структурный — вынужденные: ликвидации, фандинг, разлоки, экспирации, конец месяца;
поведенческий — паника/FOMO), Alpha Check «я на другой стороне от ___, вынужденного из-за ___», заполняемый по
сегодняшним данным (trade-news + «Цепочка до цены»); нет вынужденного — «сделки нет»; распад edge (пример: эффект
смены месяца). Это и есть шаг 1 «Пяти решений»; biasing (платить спред, если edge больше) — в шаг 2 «трение».
Заказчик хочет сфокусироваться на крипте и именно на трейдинге.

**Затем — «Пять решений»** (раздел «Торговля», масштаб — **свинг, дневки/недели**, журнал сделок **пока не делать**):
1) edge — какие условия выполнены сегодня (события, стакан/агрессоры, перекосы плеча); нет условий — нет сделки;
2) трение — спред, глубина, оценка проскальзывания по реальному стакану (`/api/crypto/orderbook`), фандинг за дни
удержания против ожидаемого хода; 3) выбор между идеями — BTC/ETH/альты: трение, волатильность, ясность;
4) размер по правилам — калькулятор блока риск-менеджмента + поправки (убеждённость, недавние результаты, тильт);
5) место сетапа в будущем — без журнала пока только объяснение.

**Ждём ответа заказчика:** (а) как ему «Крипта: цепочка до цены» и конспекты книги «The Art and Business of
Professional Trading»; (б) можно ли переделать по образцу пилота остальные 7 учебных блоков крипты.

**Раздел «Торговля» → «Крипта: цепочка до цены»** (`views/chain/crypto_chain.py`, `core/orderbook.py`): готово.
Неглубокая модель «причины → участники → стакан → цена», ~10 чисел. Глубина ±0,1% — снимки trade-news
`/api/crypto/orderbook` (с 25.10.2026, раз в 5 минут; фьючерсы — фиксированный набор binance_perp + okx_perp, Bybit
на краю полосы — не брать), fallback — Binance вживую; агрессоры — часовые свечи Binance (только закрытые часы),
против нормы за год; ликвидации — trade-news. Когда накопится 2+ недели — проверка «истончение стакана → цена».

**Учебный раздел «Крипта»** (`views/crypto/`, `core/crypto.py`): модель за 5 минут, «что сейчас», 10 блоков (порядок
для трейдера; `Block.num` — внутренний ключ, на экране `Block.order`). По методу СИГ **изнутри** переделаны «Плечо»,
«Биржи и стейблкоины», «Альткоины»: `BLOCK_SKELETON` (части), `Law.part`/`core`, `BLOCK_EDGES`, `learn.part_section`,
`learn.block_graph`. Остальные 7 — по тому же шаблону после одобрения. CVD (спот против фьючерса) — в «Плече»,
часть 4. Отчёты ревью — `reports/Ревью страницы крипты.md`, `reports/Крипта — Смыслы-Инварианты-Граф.md`.

**Прочее:** панель крипто-плеча в «Плече» есть; проверки ОИ/ликвидаций/разлоков/запасов компаний — когда накопится
